# Математика анализатора

Как приложение превращает описание ситуации в вероятность и почему этому числу можно верить.

## 1. Сценарий

Сценарий состоит из четырёх слоёв:

```
факторы (случайные) → расчётные величины (формулы) → итог (число) → событие (да / нет)
```

Один **прогон** — это один разыгранный «день». Сначала по очереди разыгрываются факторы, затем по формулам считаются величины, итог и событие. После N прогонов:

- **вероятность события** p̂ = (число прогонов, где событие произошло) / N;
- **распределение итога** — все N значений: среднее, медиана, перцентили, гистограмма.

| Слот (Snow Boom) | Анализатор |
|---|---|
| Лента барабана с весами символов | Фактор с таблицей «значение — вес» |
| Спин | Прогон |
| Выигрыш спина | Итог |
| Hit rate | Вероятность события |
| RTP | Среднее итога |
| Точный расчёт базы + Монте-Карло бонуса | Точный перебор, если возможен, иначе Монте-Карло |

## 2. Генератор случайных чисел

Используется **xoshiro128\*\***. Начальное состояние (4 × 32 бита) получается из сида через **splitmix32**. Равномерное число в [0, 1) собирается из двух 32-битных выходов с точностью 53 бита:

```
u = ((a >> 5) · 2^26 + (b >> 6)) / 2^53
```

Свой генератор вместо `Math.random()` нужен по двум причинам:
1. **Повторяемость.** Один и тот же сид всегда даёт один и тот же результат, поэтому любой расчёт можно воспроизвести.
2. **Сверка двух реализаций.** Python-эталон использует тот же генератор и тот же порядок случайных чисел, поэтому числа совпадают бит в бит.

Порядок случайных чисел: прогон за прогоном, внутри прогона факторы по порядку. Таблица, да/нет, равномерное, треугольное, данные и строки берут по одному числу; нормальное — два (метод Бокса — Мюллера); зависимый фактор — сколько нужно выбранной ветке.

## 3. Как случайное число становится значением фактора

Все распределения, кроме нормального, получаются **обратной функцией распределения** из одного числа u:

| Распределение | Правило |
|---|---|
| Таблица (значения vᵢ, веса wᵢ) | Накопленные веса Cᵢ = w₁ + … + wᵢ, W = C_k. Выбирается первое i, где u · W < Cᵢ (двоичный поиск). Это ровно остановка барабана с лентой |
| Да / нет (p) | 1, если u < p, иначе 0 |
| Равномерное [a, b] | a + (b − a) · u |
| Треугольное (a, c, b) | Если u < F_c = (c − a)/(b − a): a + √(u (b − a)(c − a)), иначе b − √((1 − u)(b − a)(b − c)). Среднее (a + b + c) / 3 |
| Нормальное (μ, σ) | μ + σ · √(−2 ln(1 − u₁)) · cos(2π u₂) |
| Из данных (x₁ … x_n) | x[⌊u · n⌋]: каждое наблюдение с шансом 1/n |

## 4. Погрешность и число прогонов

Оценка p̂ — доля «успехов» в N независимых испытаниях, поэтому её стандартная ошибка равна

```
SE = √( p̂ (1 − p̂) / N ),      95 % интервал: p̂ ± 1,96 · SE
```

Совещание, N = 1 000 000, p̂ = 0,5394: SE = 0,0005, интервал ± 0,098 %.

Сколько прогонов нужно для погрешности ± h: `N = 1,96² · p (1 − p) / h²`. При p = 0,5 и h = 0,1 % это 960 400 прогонов. Погрешность падает как 1/√N: в 100 раз больше прогонов дают в 10 раз более узкий интервал.

Если событие ни разу не произошло, интервал вида «0 ± 0» вводит в заблуждение. Тогда используется **правило трёх**: с 95 % уверенностью p < 3/N.

Для среднего итога: SE = s / √N, где s — выборочное стандартное отклонение. Перцентили считаются линейной интерполяцией между соседними значениями отсортированной выборки, как в NumPy по умолчанию.

## 5. Точный ответ перебором

Если все факторы дискретные (таблица, да/нет, данные, строки) и вариантов не больше 1–2 млн, приложение перебирает **все комбинации**. Вероятность комбинации — произведение вероятностей её значений (внутри ветки — условных):

```
P(событие) = Σ по комбинациям  P(комбинации) · [событие выполнено]
```

Перебор идёт деревом: фактор за фактором, у зависимого фактора — варианты ветки, выбранной уже перебранной причиной. Одинаковые значения склеиваются, поэтому для 60 дней по 3 столбцам выходит 19 · 20 · 10 = 3 800 вариантов, а не 60³.

Точный ответ служит проверкой. Монте-Карло на том же сценарии обязан попасть в свой 95 % интервал, а это бывает примерно в 19 случаях из 20.

## 6. «Торнадо»: какой фактор важнее

Берутся те же прогоны (до 100 тыс.), и одна величина фиксируется: сначала на 10-м, потом на 90-м перцентиле **своей** выборки. Остальные факторы остаются прежними (метод общих случайных чисел), так что разница вызвана только этим фактором. Ширина отрезка показывает, насколько фактор двигает вероятность события, или среднее итога, если события нет.

Факторы, которые **зависят** от зафиксированной величины, разыгрываются заново по её новому значению: если зафиксировать «дождь = да», автобус и обед должны стать «дождливыми». Для этого используется отдельный генератор с сидом `seed + 1000003 · (номер величины + 1)`.

## 7. Зависимые факторы

**Почему это важно.** Правило «и → умножаем» верно только для независимых событий. Если у двух рисков общая причина, их нужно считать по **формуле полной вероятности**:

```
P(A) = Σ по значениям причины  P(причина = c) · P(A | причина = c)
```

Совещание в дождь (30 % дней; в дождь опаздывают и автобус, и обед):

| | Расчёт | P(вовремя) |
|---|---|---|
| Со связью | 0,75 · (0,3 · 0,50 · 0,70 + 0,7 · 0,90 · 0,95) | 52,76 % |
| Без связи | 0,75 · 0,78 · 0,875 | 51,19 % |

Каждый фактор сам по себе в обоих случаях одинаков: P(Иван ≤ 5) = 0,3 · 0,5 + 0,7 · 0,9 = 0,78. Меняется только то, как факторы сочетаются друг с другом.

**Два вида связей в приложении:**
- **«Зависит от»** — для каждого значения причины (до 12 значений) своё распределение. Причина должна стоять выше по списку.
- **«Строки таблицы»** — прогон берёт одну строку наблюдений целиком. Все связи, которые есть в данных, сохраняются, даже неизвестные заранее. На учебных 60 днях точный ответ ровно 25/60 = 41,67 %, а если брать столбцы по отдельности — 42,47 %.

**Сравнение с наивным расчётом.** Приложение строит «версию без связей»:
- зависимый фактор заменяется смесью веток с весами P(причины);
- столбцы таблицы становятся отдельными факторами.

Каждая величина остаётся распределённой так же, но связь пропадает. Это ровно то, что получает человек, перемножающий вероятности.

Что показывает сравнение:
- Если итог — **сумма** (сроки проекта), средние совпадают, потому что среднее суммы равно сумме средних. А вот хвост тяжелее: плохие случаи приходят вместе. Проект с общей причиной «сырые требования»: срок ≤ 40 дней — 82,8 %, наивно 88,4 %; P90 — 44 дня против 40,9.
- Если итог — **максимум** («нужны все»), связь может даже повысить шанс «всё хорошо»: плохие дни собираются вместе, и хороших дней становится больше.

## 8. Попытки и «шаг за шагом»

Два составных распределения для простого режима:
- **Повтор N раз** — сумма N независимых значений. С «да / нет» внутри это число удачных попыток из N (биномиальное распределение). Пример: 8 собеседований по 15 % — хотя бы один оффер с вероятностью 1 − 0,85⁸ = 72,75 %.
- **Шагов до цели** — от «сейчас» каждый период прибавляется случайный шаг, пока не дойдём до цели (цель выше — ждём «≥», ниже — «≤»). Шаг = смесь «обычный период» и «плохой период (откат)». Если за предел (10 лет) не дошли — значение «предел + 1», и приложение честно предупреждает. Формулой такое не посчитать, Монте-Карло — легко. Проверка: шаг +1 с шансом 0,25 до цели 5 — отрицательное биномиальное, в среднем 20 шагов.
