## Часть 1. Пять этапов по плану (17 ноября 2026)

### 0. Постановка задачи

**Запрос.** Snow Boom не подошёл как учебный проект. Преподаватель сказал взять из него движок и сделать
анализатор вероятностей случайных событий — веб-приложение, которое строит вероятности по заданным распределениям
методом Монте-Карло. Пример: опоздание транспорта + задержка обеда + статистика встреч → начнётся ли совещание вовремя.

**Что сделал Claude.**
- Разобрал, что из слота можно взять как «движок»: генератор случайных чисел с сидом, выбор по весам (как лента
  барабана), массовый прогон, статистика с погрешностью, сверка с точным ответом.
- Сделал быстрый прототип на Python: совещание из задания — Монте-Карло 54,09 % ± 0,10 %, точно 54,00 %.
- Задал четыре вопроса с вариантами (см. [чат](4_чат.md)).

**Решения.**
- Всё работает в браузере, без сервера. Python — эталон для сверки.
- Сценарий: шаблоны + поле с формулой.
- Распределения первой версии (выбрал Claude по моей просьбе): таблица «значение — вес», да/нет, равномерное,
  треугольное, нормальное, из данных.
- Зависимые факторы — во второй версии.
- План из пяти этапов, после каждого — разбор и вопросы для самопроверки.

### Этап 1. Движок

- Генератор с сидом (xoshiro128**), 6 распределений, язык формул на русском (`max`, `если`, `и/или/не`),
  прогон, статистика с погрешностью, точный перебор, «торнадо» (какой фактор важнее).
- Python-эталон, совпадающий с JavaScript до последнего знака.
- **Проверки:** Python 29 тестов, движок в браузере 39. Совещание: 53,94 % ± 0,10 % при точных 54 %.

### Этап 2. Страница

- Редактор сценария в 4 шага, результаты: вероятность ± погрешность, гистограмма, «торнадо», сходимость.
- Шаблон «Два кубика»: перебор 36 вариантов = 16,67 %, Монте-Карло попадает в интервал.
- **Проверки:** движок 39, страница 24, скриншоты компьютера, телефона и тёмной темы.

### Этап 3. Данные, шаблоны, файлы

- Загрузка CSV из русского Excel, учебные данные «60 дней совещаний», шаблоны доставки и сроков проекта,
  сохранение сценария в файл.
- **Проверки:** Python 32, движок 42, страница 44.

### Этап 4. Зависимые факторы

- Общая причина («в дождь и транспорт, и обед задерживаются сильнее»), выбор дня из таблицы целиком,
  автоматическое сравнение с расчётом, где связь забыта.
- Совещание в дождь: 52,8 % со связью, 51,2 % без неё.
- **Проверки:** Python 42, движок 52, страница 67.

### Этап 5. Оформление и публикация

- README, описание математики и архитектуры, скриншоты.
- **Решения:** открытый код + живое демо на GitHub Pages; ветки `main` и `develop`; переписку и заметки не публиковать.
- Опубликовано, демо проверено на живом сайте.

## Часть 2. Доработки по отзывам (17–18 ноября 2026)

### 1. Простой режим

**Запрос.** Я открыл приложение как пользователь и не понял, как им пользоваться: непонятно всё, начиная со
«Случайных факторов». Приложение должно быть удобным и понятным.

**Решения.** Пользователь — обычный человек. По умолчанию — простой режим без формул, редактор остаётся
«режимом специалиста».

**Сделано.** 4 простых вопроса, ответ «54 из 100», 100 квадратиков, «что поможет больше всего». Страница: 87 проверок.

### 2. Своя ситуация, а не готовые примеры

**Запрос.** Обычному человеку не нужны готовые события — он считает свою ситуацию. Мои примеры: пожму ли я 100 кг,
сколько времени нужно, чтобы похудеть.

**Сделано.** 4 схемы (части складываются / ждём всё / иду к цели шаг за шагом / несколько попыток), вопрос
«Что вы знаете о числе?» (точно, примерно, может случиться, как было раньше), сравнение вариантов, сохранение
расчётов, ссылка. В движок добавлены «повтор N раз» и «шагов до цели». Проверки: Python 49, движок 56, страница 93.

### 3. Вопрос своими словами

**Запрос.** Слишком топорно: если я хочу спросить «какая вероятность найти работу до Нового года», я не понимаю,
куда это вписать.

**Сделано.** Старт с поля вопроса, программа узнаёт 12 тем, срок и числа. Новая схема «Получится ли до срока».
Проверки: Python 54, движок 58, страница 100.

### 4. Ноль и логика поиска работы

**Запросы.** Почему шанс нельзя поставить в ноль? Работа найдена, только если дали оффер, а собеседования могут
быть и без оффера.

**Сделано.** Повторный щелчок по первому кружку — «0 из 10». Для работы — цепочка «отклики → приглашения →
оффер → оффер подходит». Страница: 103 проверки.

### 5. Анализ похожих приложений

**Запрос.** Посмотри похожие приложения в интернете; нужно нормально рабочее и удобное приложение.

**Сделано.** Разобраны Guesstimate, Squiggle, Causal, @RISK, прогнозы сроков Magennis, калькуляторы пенсии
FIRECalc. Взяли: ответ датами и график «шанс к каждой дате», проверку на оптимизм («если всё на четверть хуже»),
компактную форму. Страница: 104 проверки.

### 6. Главный поворот: универсальный конструктор

**Запрос.** Остановились и подумали, для чего приложение. Под некоторые условия расчёт некорректен, а новое
условие программа не поймёт.

**Вывод.** Угадывать тему по словам — тупик: любая новая ситуация ломает программу. В задании сказано
«по **заданным** распределениям», то есть человек сам задаёт, что случайно и как.

**Сделано.** Конструктор из 4 шагов:
1. Что прогнозируем.
2. Случайные факторы: точно / примерно / любое от–до / может случиться / да-нет / варианты с процентами / по данным;
   связь с общей причиной.
3. Как получается итог: сумма, самое большое, самое маленькое, разница, произведение, «если … то … иначе …», своя формула.
4. Условие успеха.

При первом заходе сразу открыт пример из задания — 54 из 100. Расчёты «во времени» (цель, срок, попытки)
оставлены отдельно. Проверки: Python 54, движок 58, страница 108.

### 7. Убран режим специалиста, публикация

**Запрос.** Убери режим для специалиста. Затем — «отправляй».

**Сделано.** На странице только конструктор. Внизу ответа остались свёрнутые «Подробности расчёта»
(точная вероятность ± погрешность, перебор, формулы). Изменения отправлены на GitHub, живой сайт обновлён.

### 8. Отзыв преподавателя (18 ноября)

**Запрос.** Преподаватель посмотрел приложение: доработать правую часть (ответ) — непонятно; добавить отчёт в PDF;
сделать отдельную ветку с описанием работы с Claude.

**Сделано.**
- Ответ словами из условия: «в 54 случаях из 100 «Задержка совещания» не больше 5 мин — примерно каждый второй раз»,
  пояснение «как посчитано», подписи «не больше 5 мин / больше 5 мин» вместо абстрактных «выполнится / не выполнится».
- «Сколько выходит» простыми фразами, гистограмма внутри этого блока с пояснением цветов.
- «Что поможет»: «Если «Переговорка занята» всегда «нет» — 54 → 72 из 100».
- Кнопка «📄 Отчёт в PDF»: две страницы A4 — ответ, всё, что задано (факторы и расчёты словами), график,
  советы и метод расчёта.
- Эта ветка `process`.
- **Проверки:** страница 44, движок 58.

### 9. Разбор проекта и уборка (18 ноября)

**Запрос.** Проанализировать всё, что есть. Затем — сделать предложенное: убрать лишний код, вернуть загрузку данных
из Excel, обновить документацию, поправить мелочи интерфейса.

**Что показал разбор.** Приложение отвечает заданию и проверено, но после переделок остался мёртвый код (около 500 строк),
пропала загрузка CSV (ушла вместе с режимом специалиста), устарели числа в документации и скриншоты.

**Сделано.**
- Убран код старых версий: угадывание темы по словам, схемы «части складываются» и «ждём всех», цепочка для поиска работы,
  неиспользуемые графики и 66 правил оформления. Старые сохранённые расчёты сами открываются в конструкторе.
  Код стал на 500 строк короче.
- Фактор «по данным»: кнопка «📂 Загрузить из файла» и перетаскивание файла. Понимает CSV из русского Excel,
  если в файле несколько столбцов с числами — спрашивает, какой взять. На файл .xlsx — подсказка сохранить как CSV.
- «Примеры формул» под своей формулой — с именами из этого же расчёта.
- Большие суммы без ложной точности: «62 200 ₽» вместо «62 175 ₽».
- Примеры особых расчётов на стартовом экране: жим 100 кг, похудение, накопления, работа, собеседования, экзамен.
- Обновлены README, описание математики и архитектуры, все скриншоты.
- **Проверки:** Python 54, движок 58, страница 52.

## Ключевые решения

| Решение | Почему |
|---|---|
| Всё в браузере, без сервера | Миллион прогонов считается меньше чем за секунду; работает без интернета, легко показать |
| Две реализации движка (JavaScript + Python) | Независимая проверка каждого числа |
| Свой язык формул на русском, без `eval` | Безопасно и понятно, ошибки описаны словами |
| Генератор с сидом | Тот же расчёт всегда даёт те же числа — результат можно проверить и повторить |
| Ответ «N из 100» вместо процентов | Обычному человеку так понятнее |
| Конструктор вместо угадывания темы | Работает для любой ситуации, точно по заданию |
| Публикация только по команде | Контроль над тем, что уходит в интернет |
